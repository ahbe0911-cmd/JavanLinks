# لینک‌های کاربردی کافینت جوان — فاز ۱

نسخه 0.1.0، اسکلت مستقل نرم‌افزار ویندوزی بر پایه Python و PySide6/Qt WebEngine.

## اجرای ویندوز

پیش‌نیاز پیشنهادی: Windows 10/11 نسخه ۶۴ بیتی، Python 3.11 یا 3.12 نسخه ۶۴ بیتی و اینترنت برای نصب وابستگی‌ها. فایل ZIP را استخراج و `run.bat` را اجرا کنید. یا در PowerShell از پوشه پروژه:

```powershell
py -3.12 -m venv .venv
.\.venv\Scripts\python.exe -m pip install -r requirements.txt
.\.venv\Scripts\python.exe main.py
```

اگر فونت Vazirmatn را در Windows نصب کنید، برنامه از آن استفاده می‌کند. همچنین می‌توانید فایل TTF رسمی را به `assets/fonts/` اضافه کنید. در غیاب فونت وزیرمتن، فونت سیستمی جایگزین می‌شود. فایل فونت همراه این بسته نیست.

## امکانات فاز اول

- پنجره تمام‌اندازه با چیدمان RTL و منوی راست، قابل جمع‌کردن.
- صفحه اصلی داخلی مستقل از اینترنت و شش لینک نمونه در چهار دسته.
- جستجوی زنده نام، دسته، توضیحات و دامنه با نرمال‌سازی حروف فارسی/عربی.
- یک نمای Qt WebEngine، نشانگر پیشرفت و وضعیت خطای بارگذاری.
- پروفایل موقت مرورگر؛ نشست کاربران تا زمان خروج کامل از برنامه برقرار است. این نسخه جایگزین سامانه مدیریت نشست مشتریان کافی‌نت نیست.

## آزمون

```powershell
.\.venv\Scripts\python.exe -m unittest discover -s tests -v
.\.venv\Scripts\python.exe -m tests.smoke_gui
```

آزمون اول بدون Qt نیز اجرا می‌شود؛ آزمون دوم به Qt و محیط گرافیکی نیاز دارد. برای تست دستی، لینک‌های نمونه را باز کنید و نمایش وب‌سایت، ورود، ریدایرکت و خطاهای احتمالی را بررسی کنید. لینک‌ها نمونه‌اند و در این محیط به‌صورت زنده آزموده نشده‌اند.

## مرزبندی فازها

فاز ۲: CRUD، فایل HTML محلی، JSON، پشتیبان‌گیری و بازیابی. فاز ۳: تب‌ها، کنترل مرورگر، چاپ، زوم، دانلود و مدیریت پنجره‌های جدید. فاز ۴: بسته‌بندی EXE، آیکون و GitHub Actions. در فاز ۱ دانلود و پنجره‌های جدید عمداً فعال نشده‌اند. سازگاری تمام سامانه‌های بانکی/دولتی یا کاهش مصرف حافظه در مقایسه با Chrome تضمین نشده است؛ Qt WebEngine نیز مبتنی بر Chromium است. از مرورگر روی سامانه‌های حساس تا تکمیل و آزمون امنیت و سازگاری استفاده عملیاتی نشود.

`main.py`: نقطه ورود؛ `javan/app.py`: راه‌اندازی؛ `catalog.py`: مدل و جستجو؛ `sidebar.py`: منوی خدمات؛ `browser.py`: مرورگر؛ `window.py`: پنجره؛ `theme.py`: ظاهر و فونت؛ `tests/`: آزمون‌ها.

## نسخه 0.5.0 — حسابداری یکپارچه

دکمه سبز «حسابداری» در هدر، فایل حسابداری v3 را بدون اینترنت در یک تب ثابت باز می‌کند. این تب فقط هنگام اولین کلیک ساخته می‌شود و کلیک مجدد به تب موجود برمی‌گردد. منطق مالی و کلیدهای LocalStorage فایل اصلی حفظ شده‌اند. HTML به مسیر دائمی `accounting/index.html` در پوشه AppLocalDataLocation کپی می‌شود؛ پروفایل اختصاصی پایدار این پوشه از نشست اینترنتی جداست. تغییر فایل EXE یا مسیر استخراج موقت آن، این مسیر و پروفایل را تغییر نمی‌دهد. داده‌های مرورگر قدیمی خارج از این برنامه خودکار وارد نمی‌شوند؛ از قابلیت پشتیبان JSON داخل حسابداری استفاده کنید.

فونت وزیرمتن همراه بسته ساخته می‌شود. دکمه «فونت‌ها» اجازه می‌دهد ZIP/TTFهای روزنامه، نازنین و چهار وزن وزیرمتن را مستقیماً از دیسک وارد کنید؛ فایل‌های اضافی ZIP استخراج نمی‌شوند. روزنامه برای عنوان برند و نازنین برای متن توضیحی فاکتور چاپی A4/A5 استفاده می‌شوند، و وزیرمتن برای رابط و مبالغ. فایل‌های روزنامه و نازنین در مخزن عمومی منتشر نشده‌اند. دسترسی خارجی HTML حذف شده، ساعت در تب پنهان متوقف می‌شود و به‌روزرسانی پیشرفت دانلود به‌صورت تجمیعی انجام می‌شود.

برای حفظ اطلاعات مالی، پشتیبان JSON داخلی حسابداری را به‌طور منظم در مسیر دیگری نگه دارید؛ پشتیبان مدیریت لینک‌ها شامل داده حسابداری نیست. حذف پوشه داده ویندوز یا پروفایل اختصاصی ممکن است اطلاعات را از بین ببرد. تغییرات CPU/RAM باید روی ویندوز واقعی اندازه‌گیری شوند.

## مرحله P1-الف — مدل رابطه‌ای آزمایشی SQLite (schema 2)

- جداول جداگانه خدمات، فاکتورها، اقلام فاکتور، نسیه، فراداده و audit_log؛ مقادیر اصلی تاریخی بدون بازمحاسبه حفظ می‌شوند.
- نسخه schema 1 با پشتیبان مستقل قبل از مهاجرت و مقایسه دقیق داده به schema 2 منتقل می‌شود. جدول snapshot قدیمی دست‌نخورده باقی می‌ماند. نسخه قبلی از schema 2 پشتیبانی نمی‌کند؛ برای بازگشت باید از پشتیبان معتبر استفاده شود.
- حذف از رابط فعلی به غیرفعال‌سازی رکورد در SQL تبدیل می‌شود. ثبت تغییرات قبل/بعد در audit_log با trigger جلوگیری از UPDATE/DELETE انجام می‌شود؛ این محدودیت در برابر مدیر سیستم با دسترسی مستقیم به دیتابیس، تضمین ضدتقلب نیست.
- API سازگار با نسخه قبلی همچنان کل دفتر را منتقل می‌کند و پشتیبان JSON کامل می‌سازد؛ کاهش واقعی CPU/RAM هنوز اندازه‌گیری نشده است. ذخیره افزایشی رکوردهای تغییرکرده در SQLite شروع شده، ولی صفحه‌بندی، API عملیات جزئی، ارتباط نسیه با فاکتور، پرداخت جزئی، PIN مدیر و نمایش گزارش حسابرسی در رابط هنوز باقی هستند.
- آزمون‌های جدید شامل مهاجرت schema 1، شکست پشتیبان پیش از مهاجرت، حذف نرم، ثبات audit، بازگردانی تراکنش و تعویض شماره فاکتور هستند.


## مرحله P1-ب — نسیه و حفاظت مدیر

- فاکتور نسیه جدید خودکار یک بدهی متصل ایجاد می‌کند. بدهی‌ها و فاکتورهای قدیمی به‌صورت خودکار بر اساس نام تطبیق داده نمی‌شوند؛ از ثبت مضاعف تاریخی جلوگیری شده است. مانده فاکتورهای نسیه قدیمی بدون ارتباط هنوز نیازمند تطبیق دستی است.
- پرداخت جزئی، تسویه و مشاهده سوابق وصول در رابط. اصل مبلغ حفظ و دریافت بیشتر از مانده رد می‌شود. پرداخت‌ها فعلاً در payload ردیف نسیه ذخیره و تغییرات آن‌ها در audit_log ثبت می‌شوند؛ جدول مستقل و API افزایشی پرداخت هنوز در نقشه راه است.
- حذف یا تغییر مبلغ فاکتور دارای وصول ثبت‌شده مسدود است. برگشت وصول نیازمند PIN و ثبت در audit_log است. فاکتورهای بدون وصول با مجوز مدیر قابل ویرایش/حذف نرم هستند.
- اولین عملیات حساس، در پنجره بومی Qt، تعریف PIN شش تا دوازده رقمی انگلیسی و تکرار آن را درخواست می‌کند. PIN به‌صورت scrypt با salt تصادفی در accounting-data/manager-pin.json ذخیره می‌شود و در JSON مالی نیست. مدیر باید خودش اولین بار آن را تعریف کند؛ این کنترل امنیت محلی است و در برابر مدیر سیستم دارای دسترسی مستقیم به فایل‌ها یا حذف فایل PIN تضمین ندارد. امکان تغییر/بازیابی PIN و محدودیت تلاش ورود هنوز اضافه نشده است.
- تست‌های Python و JS برای مانده، وصول بیش از حد، پیوند نسیه، رد عملیات حساس و PIN افزوده شده‌اند. اجرای واقعی پنجره PIN و چاپ هنوز نیازمند آزمون دستی ویندوز است.


## مرحله P2-الف — کنترل منابع و امنیت مرورگر

- حالت سبک اختیاری: هر ۳۰ ثانیه فقط تب‌های وب پنهان که Qt توقف را توصیه می‌کند Freeze می‌شوند، نه Discard. تب جاری با انتخاب دوباره فعال می‌شود؛ حسابداری، HTML محلی، چاپ و دانلود فعال مستثنا هستند. زمان‌سنج در حالت عادی خاموش است. اعداد مصرف CPU/RAM هنوز اندازه‌گیری نشده‌اند.
- درخواست دوربین/میکروفون فقط برای HTTPS با تأیید صریح کاربر؛ سایر مجوزها رد می‌شوند. خطای TLS اجازه عبور ندارد. اتصال HTTP در نوار وضعیت مشخص است.
- هشدار فایل اجرایی در دانلود، به‌روزرسانی سلول‌های تغییرکرده به‌جای ساخت مجدد همه سلول‌ها.
- گزارش محلی چرخشی در logs، بدون URL و متن خطا یا داده مالی؛ شناسه نوع خطا و محل کد ثبت می‌شود. محافظت در برابر DNS rebinding، صف کامل دانلود، چاپگر حرارتی و اندازه‌گیری سخت‌افزار باقی مانده‌اند.
- تغییرات ظاهری سبک و بدون انیمیشن دائمی؛ هیچ ویژگی حسابداری حذف نشده است.


## مرحله P2-ب / P3-الف — رابط دسکتاپ و بسته اجرای سریع

- منوی راست قابل تغییر عرض (235 تا 460 پیکسل منطقی)، حفظ وضعیت جمع‌شدن دسته‌ها در طول نشست و بازشدن نتیجه‌های جستجو؛ ابزارهای کم‌کاربرد در منوی جداگانه، تمام‌صفحه F11 و نوار ابزار فشرده‌تر.
- بسته تک‌فایلی قبلی همچنان تولید می‌شود. بسته اختیاری JavanLinks-Fast-Windows-x64.zip بر مبنای PyInstaller onedir نیز تولید و جداگانه با آزمون‌های راه‌اندازی و ذخیره/بازیابی مالی آزمایش می‌شود. تمام ZIP را استخراج کنید و JavanLinks.exe را از داخل پوشه اجرا کنید؛ پوشه _internal لازم است.
- دو بسته از همان مسیر استاندارد داده استفاده می‌کنند؛ اجرای هم‌زمان آن‌ها مجاز نیست. مدت راه‌اندازی و مصرف RAM هنوز روی دستگاه واقعی اندازه‌گیری نشده است؛ onedir هزینه استخراج onefile را حذف می‌کند، نه هزینه ذاتی WebEngine.
- نسخه وابستگی‌ها از اجرای موفق a3f3dd2 استخراج و ثابت شده‌اند؛ این فهرست قفل نسخه است، نه قفل هش یا امضای دیجیتال. انتشار خودکار نسخه اصلی تغییر نکرده؛ بسته سریع فعلاً Artifact آزمایشی است.


## کنترل نهایی بسته اجرایی

آزمون seed/write/read علاوه بر مهاجرت و ماندگاری فاکتور، اکنون از طریق رابط واقعی یک فاکتور نسیه ۱۲۳۴۵ تومانی و وصول جزئی ۲۳۴۵ تومانی ایجاد می‌کند؛ وجود تنها یک بدهی مرتبط، مانده ۱۰۰۰۰ تومان، عدم تغییر اصل مبلغ و بازیابی پس از خروج کامل برنامه در هر دو بسته اجرایی بررسی می‌شوند. مقدار پنجره prompt صرفاً در اجرای آزمون از داده مصنوعی تأمین می‌شود؛ آزمون دستی ورود PIN و چاپ واقعی، اندازه‌گیری منابع و بازبینی بصری همچنان ضروری‌اند.


## مرحله آزمایشی Edge WebView2

- موتور بومی Microsoft Edge WebView2 به کمک یک پنجره مستقل چندزبانه WinForms/.NET 8 اضافه شده است. وقتی بسته Edge موجود باشد، لینک‌های وب و نشانی اینترنتی به صورت پیش‌فرض به آن فرستاده می‌شوند. دکمه Edge امکان بازگشت به Qt را فراهم می‌کند؛ حسابداری و HTML محلی همیشه با Qt باقی می‌مانند.
- یک پردازش میزبان برای نشست و یک user-data-folder مشترک برای تمام تب‌های Edge، کش معمول WebView2، حفظ تب زنده بدون Navigate هنگام انتخاب دوباره لینک، مجوز صریح دوربین/میکروفون و عدم عبور از خطای TLS. کاربر می‌تواند در پنجره Edge چاپ، PDF، بزرگ‌نمایی و دانلودهای بومی WebView2 را انجام دهد؛ دانلودهای Edge در مدیر دانلود Qt نمایش داده نمی‌شوند.
- برای پایان جلسه، میزبان بسته می‌شود و پوشه نشست اختصاصی تا حد امکان حذف می‌شود (پاکسازی مجدد در شروع بعدی). فایل‌های دانلودشده حذف نمی‌شوند. بستن پنجره Edge نیز تب‌های آن را از بین می‌برد. کش در طول یک نشست حفظ می‌شود، نه به قیمت باقی گذاشتن اطلاعات مشتری بین نشست‌ها.
- در صورت مشکل کپچا، دکمه «Edge اصلی» نشانی جاری را در Microsoft Edge مستقل InPrivate باز می‌کند؛ آن نشست خارج از مدیریت کافی‌نت است. این تغییر کپچا را دور نمی‌زند و سازگاری سامانه قضایی نیازمند آزمون واقعی است.
- کش حافظه Qt به ۱۹۲ MiB افزایش یافت؛ زبانه‌های موجود پس از ویرایش لینک‌های دیگر حفظ می‌شوند. این تغییر به‌تنهایی تضمین کاهش RAM نیست. آزمون ساخت، WebView2 واقعی را با سرور محلی و حفظ مقدار فرم هنگام انتخاب مجدد تب می‌سنجد. عملکرد اینترنت ایران، چاپگر و سرعت دستگاه کاربر هنوز اندازه‌گیری نشده‌اند.
- ساخت بومی: PowerShell `./scripts/build_edge.ps1`، سپس `./build_windows.ps1`. نیازمند WebView2 Evergreen Runtime؛ اگر موجود نبود، از سایت رسمی Microsoft نصب شود. بسته‌ها شامل میزبان self-contained .NET هستند و بزرگ‌تر می‌شوند.
